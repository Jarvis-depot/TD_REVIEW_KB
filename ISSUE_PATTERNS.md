## USB3_TESTSUITE X-2025.12 — RIT TD 1.8 HCRST asserted while xHC running (source-confirmed precondition violation)

- **Evidence/version:** `Jarvis-depot/USB3_TESTSUITE@f33f727ca4f581a0a15b22524fa453707f62eb08`, `svt/usb_svt/X-2025.12/sverilog/src/vcs/svt_usb_xhci_system_virtual_sequence_collection.svp`, `PORTLI_Register_Test()` lines 1110–1125. User-provided `xhc_usbcmd_reg` schematic waveform and test log show 0x5→0x7→0x0, `Issue HCRST Successfull (reg_write_data=7)`. Actual user's simulation git commit/config not yet linked to inspected GitHub revision.
- **Source-confirmed trigger:** TS reads USBCMD and sets `reg_write_data[1]=1` without clearing R/S[0] or checking `USBSTS.HCHalted[0]`. If USBCMD bit0 had been 1, it writes HCRST=1 together with R/S=1. User's 0x7 indicates the triggering condition actually occurred in their waveform.
- **Normative contradiction:** Intel xHCI Rev 1.2 §5.4.1 USBCMD.HCRST: software shall not set HCRST while USBSTS.HCHalted=0, else undefined results. §5.4.2 USBSTS.HCHalted: HCH=0 whenever USBCMD.R/S=1. The request with USBCMD=0x7 is not a valid compliant host reset stimulus.
- **Effect and scope:** A DUT can still reset and show PORTLI 1→0 and CNR 1→0, yet that does not validate DUT behavior under a spec-conforming reset stimulus. This is an environment sequence issue, not proof of DUT bug or a proven reason for accompanying Device VIP Class-10 timer expiry/Recovery.
- **Safe remediation:** after confirming induced PORTLI.Link_Error_Count=1, clear R/S, wait HCHalted=1, then assert HCRST with R/S=0, poll HCRST clear and CNR clear, and re-check PORTLI=0. Preserve equivalent TD1.08 objectives. Log HCH, HCRST, CNR, PORTLI, and the original VIP timeout/Recovery messages; approve waiver only if reset-compliant rerun demonstrates errors are limited to transitory recovery without impact.
- **Secondary coverage gap:** same TD task Step6 lines 1163–1175 tests writing nonzero PORTLI followed by read-zero, rather than proving assertion 5.4.10.1#5 write-zero clears a previously nonzero counter. Source-level coverage discrepancy, independent of the two VIP errors.
